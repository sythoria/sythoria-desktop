# Review tab update plan

The reference screenshot is a visual example. The app's registered workspace, project exclusions, Git diff, and current theme remain the sources of truth.

1. **Full workspace tree and collapse controls.** Replace the changed-file list with a read-only, lazily loaded directory tree using `project_browse_begin` and `project_list_dir`. Show ordinary workspace files as well as changed files, including deleted paths that no longer exist on disk. Let folder buttons expand and collapse. Expand the selected file's ancestors so links from chat still reveal their target. Selecting a changed file opens its diff; selecting an unchanged file opens the bounded file preview. Keep loading and read errors visible in the tree.
2. **File search.** Add a search field above the tree. Search all workspace file paths through the existing project-scoped glob command so files in unopened folders can be found. Show path context in results, retain the selected diff, support clearing the query, and handle empty/error states. Keep normal browsing lazy when search is empty.
3. **Hide and show the file list.** Add an accessible toolbar button that toggles the right rail. The diff or preview should use the available width, and the control must remain available to restore the rail. Preserve the selected file and current tree state while hidden.
4. **Resizable file list.** Add a pointer and keyboard accessible divider between the code pane and file rail. Clamp its width so both panes remain usable, and keep the chosen width while the Review tab remains mounted. On narrow layouts, use the existing stacked arrangement without a horizontal divider.
5. **Change markers.** Show distinct added, modified, deleted, and renamed markers on file rows. Mark ancestor folders with a smaller indicator when any descendant changed. Derive all markers from the current Git diff/status and keep them visible in search results, with accessible labels and tooltips.
6. **Unmodified lines.** Strengthen the omitted-context rows in the diff: display their counts and position clearly with separate styling from added/deleted code, including consistent singular/plural labels and readable line-number boundaries. Preserve progressive rendering for large patches and keep patch metadata out of code rows.
7. **Rounded visual system.** Apply the app's existing radius, border, surface, hover, focus, and color tokens to the Review toolbar, code card, tree rail, rows, search, controls, and omitted-context labels. Avoid hardcoded theme colors and keep the layout responsive.

Each item is implemented and committed separately. Verification is limited to focused tests for the touched behavior and the frontend type/build checks required to catch compile failures; no visual QA or app launch is part of this work.
